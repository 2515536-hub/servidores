DNS

¿Qué es DNS?

DNS (Domain Name System) es el servicio encargado de traducir nombres legibles para las personas, como ejemplo.com, a direcciones IP que los equipos pueden entender. Sin DNS, la navegación y muchos servicios de red serían mucho más difíciles de localizar y administrar.

Características principales de DNS:

Resolución de nombres

Permite asociar dominios, subdominios y hosts a direcciones IP y a otros recursos de la red, con la misma lógica que un directorio telefónico para Internet.

Administración de zonas

Los administradores pueden definir registros como A, AAAA, MX, CNAME y TXT para controlar cómo se resuelven los servicios y dominios internos o públicos.

Caché y redundancia

Los servidores DNS pueden almacenar respuestas temporales y operar en jerarquías para mejorar la velocidad, la disponibilidad y la tolerancia a fallos.

Protocolos y tecnologías habituales:

  • Puerto 53 con tráfico UDP para consultas rápidas y TCP cuando se requiere transferencia de zonas mayores.
  • Registros A, AAAA, CNAME, MX, TXT y NS para definir la identidad y servicios del dominio.
  • SOA y TTL para controlar la autoridad de zona y el tiempo de caché de las respuestas.
  • Jerarquía de servidores raíz, TLD y autoritativos para distribuir la resolución de forma escalable.

Ventajas de usar DNS:

  • Permite acceder a servicios por nombre en lugar de recordar direcciones IP.
  • Simplifica la administración de servidores, aplicaciones y dominios.
  • Mejora la escalabilidad con zonas, subdominios y delegación de autoridad.
  • Facilita la disponibilidad de servicios internos y externos con caché y redundancia.
  • Es esencial para la navegación, correo, autenticación y servicios web.

Desventajas de usar DNS:

  • Si el servicio falla, los nombres no se resuelven correctamente.
  • Un registro mal configurado puede causar errores de acceso o pérdida de servicios.
  • La caché y la propagación de cambios requieren planificación para evitar inconsistencias.

Funcionamiento de DNS:

Cuando un cliente quiere acceder a un nombre, consulta primero a un servidor resolver. Si no tiene la respuesta en caché, realiza la búsqueda en la jerarquía DNS hasta llegar al servidor autoritativo que contiene la zona correspondiente. Ese servidor devuelve la dirección IP asociada y el cliente puede conectarse al servicio solicitado.

Casos de uso y valor del servicio:

Servicios web y internos

DNS permite publicar sitios, aplicaciones, correos y servicios internos usando nombres fáciles de recordar. Esto facilita la operación diaria y la administración de red.

Disponibilidad y organización

Con registros bien definidos, subdominios y servicios distribuidos, DNS ofrece un punto central para la resolución de nombres y la gestión de infraestructura.

Información técnica útil

Aspecto Detalle
Puertos principales 53/UDP para consultas normales y 53/TCP para transferencia de zonas y respuestas mayores.
Registros comunes A, AAAA, CNAME, MX, NS, TXT y SOA para definir nombres, IPs y servicios del dominio.
Servidor autoritativo Es el que contiene la zona oficial del dominio y responde con información definitiva.
Casos típicos Publicar sitios web, servicios de correo, servidores internos, balanceadores y aplicaciones.
Consideraciones Es importante mantener registros correctos, TTL adecuados y copias de seguridad de la zona.

    Preparación de la máquina virtual

  • Para la instalacion de nuestro servidor DHCP es necesaria antes haber instalado los paquetes.

    • sudo apt update

    sudo apt install -y isc-dhcp-server bind9 bind9utils vsftpd

  • Aplicaremos un comando para configurar las opciones generales del DNS

    • sudo nano /etc/bind/named.conf.options

  • Ahora vamos a declarar las zonas del DNS

    • sudo nano /etc/bind/named.conf.local

  • Configuraremos la zona directa

    • sudo nano /etc/bind/db.midominio.local

  • Configuraremos la zona inversa

    • sudo nano /etc/bind/db.192.168.30

  • Validaremos y reiniciaremos el servicio

    • sudo named-checkconf

    sudo named-checkzone midominio.local /etc/bind/db.midominio.local

    sudo named-checkzone 1.168.192.in-addr.arpa /etc/bind/db.192.168.1

    sudo systemctl restart bind9

    sudo systemctl enable bind9

    sudo systemctl status bind9

Conclusión sobre DNS:

El servidor DNS automatiza la resolución de nombres de dominio en una red, mejorando la gestión y reduciendo errores de configuración. Su implementación segura requiere una adecuada planificación y monitoreo.
